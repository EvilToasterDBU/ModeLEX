# Кастомизация ModLEX — спецификация (v0, решения согласованы 2026-09-19)

Две независимые вещи, которые не смешиваются:

- **Оформление инстанса** — создатель сборки задаёт, как выглядят хедер, карточка, страница инстанса,
  логотип и звук. Едет вместе со сборкой.
- **Сцена (ModLEX Scene)** — оформление самого лаунчера: фон, раскладка главной, эффекты на карточках.
  Ставит пользователь, каталог сцен — отдельный репозиторий.

Общие принципы:

1. **Только данные, никакого кода от третьих лиц в основном процессе.** Оформление инстанса — ассеты и JSON
   с проверяемыми полями. Сцена — HTML в песочнице без доступа к сети и данным лаунчера.
2. **Карточки рисует лаунчер.** Ни сцена, ни автор не подменяют нативную карточку целиком: клики, ПКМ,
   фокус и доступность остаются родными.
3. **Пользователь главный.** Любое чужое оформление отключается, анимации отключаются отдельно.
4. **Вперёд-совместимость.** Во всех форматах есть `schema`/`api`, неизвестное молча игнорируется.
5. **Без готовых эффектов в настройках** — только инструменты для авторов.

## Часть A. Оформление инстанса

### A.1. Где лежит

В папке инстанса — каталог `modlex/`:

```
<инстанс>/modlex/
  modlex.json        манифест (обязателен)
  header.webp        полоска инстанса в списке
  card.webp          лицо карточки
  page.webp          баннер/фон страницы инстанса
  logo.webp          логотип (может быть анимированным)
  hover.ogg          звук при наведении на хедер
  ambience.ogg       звук на странице инстанса
```

Имена файлов свободные — манифест указывает на них. Пути только относительные, внутри `modlex/`
(никаких `..`, абсолютных путей и ссылок в интернет). Копирование/дублирование инстанса копирует и
оформление, потому что оно лежит в его папке.

Кастомайзер создаётся как расширение существующего редактора иконок инстанса (`icon-editor-modal`):
дополнительные вкладки «Хедер», «Карточка», «Страница», «Логотип», «Звук». Сам генерируемый значок
остаётся в `icon_config` как сейчас.

### A.2. Манифест `modlex.json`

```json
{
  "schema": 1,
  "author": "Название команды",
  "header": {
    "image": "header.webp",
    "hover": "header-hover.webp",
    "animate": "hover",
    "focus": [0.5, 0.4],
    "accent": "#7dd3fc"
  },
  "card": { "image": "card.webp", "hover": "card-hover.webp", "animate": "hover", "accent": "#7dd3fc" },
  "page": { "banner": "page.webp", "background": "page-bg.webp", "animate": "always" },
  "logo": { "file": "logo.webp" },
  "sound": {
    "hover": { "file": "hover.ogg", "volume": 0.4 },
    "page":  { "file": "ambience.ogg", "volume": 0.3, "loop": true }
  }
}
```

`image` — то, что видно, пока на элемент не наведён курсор (обычная картинка). `hover` — что показывается
при наведении: статичная картинка или анимация (webp/gif/apng); необязателен. `animate` выбирает автор:
`hover` (по умолчанию), `always` или `never`; пользователь может переопределить в настройках (см. A.5).

Все блоки необязательны. Значения проверяются: цвета `#rrggbb`, числа в диапазонах, перечисления из
известного списка. Ошибочный блок отбрасывается, остальные применяются.

### A.3. Ассеты и лимиты (предложение, цифры уточнить)

| Что | Форматы | Лимит |
|---|---|---|
| Картинки | webp, png, jpg | ≤ 8 МБ, сторона ≤ 4096 px |
| Анимация | animated webp, gif, apng | ≤ 15 МБ, ≤ 1080 px |
| Звук | ogg, mp3, opus | ≤ 10 МБ, ≤ 5 мин |
| Вся папка `modlex/` | — | ≤ 64 МБ, ≤ 64 файла |

**Рекомендуемые размеры** (по реальной вёрстке; редактор показывает их у каждой картинки и предупреждает, если
файл сильно отличается):

| Картинка | Размер | Где показывается |
|---|---|---|
| Хедер (в покое и при наведении) | 1920×160 (12:1) | полоска «Jump in»: ширина от 670 px, высота от 80 px; в узком окне режется по бокам |
| Карточка (в покое и при наведении) | 600×800 (3:4) | карточка библиотеки; минимальная ширина 112 / 160 / 224 px для «маленьких / средних / крупных», высота ≈ ширина + 54 px |
| Баннер страницы | 1920×200 (≈10:1) | шапка страницы инстанса (значок, название, кнопки лежат поверх); обрезается по скруглённому углу панели |
| Фон страницы | 1920×1080 (16:9) | под всей страницей инстанса |
| Логотип | 512×512 (1:1, прозрачный фон) | вместо значка на странице инстанса |

**Иконка инстанса** (`icon`) едет вместе с оформлением: при экспорте лаунчер кладёт готовую иконку в
`modlex/icon.png` и пишет в манифест `"icon": { "file": "icon.png", "config": { background, symbol } }` (`config` —
id фона и символа, если иконка сгенерирована в редакторе иконок; тогда она остаётся редактируемой). При импорте
сборки иконка применяется к новому инстансу, если у него ещё стандартная; при явном импорте архива оформления
заменяет текущую. Иконки с сайта (ссылка) не копируются — у другого лаунчера они подтянутся сами.

**Слой поверх** (`overlay`) — необязательная полупрозрачная картинка (PNG/WebP/GIF) у хедера, карточки и шапки
страницы: рисуется выше значка, текста и кнопок, но не перехватывает мышь, а прозрачные места оставляют содержимое
видимым. Свои `overlayFocus`, `overlayZoom`, `overlayOpacity` (0.05..1); анимация подчиняется `animate` блока. Размеры
те же, что у картинки этого элемента. Слот файла: `header.overlay`, `card.overlay`, `page.overlay`.

Кадр задаётся парой `focus` [x, y] (доли 0..1, какую часть картинки оставлять при обрезке) и `zoom` (1..3).
У хедера и карточки они лежат в самом блоке; у страницы отдельно для баннера и фона: `bannerFocus`,
`bannerZoom`, `backgroundFocus`, `backgroundZoom`. Редактор — как аватарка в мессенджере: рамка с реальными
пропорциями, картинку можно таскать и приближать, поверх макет интерфейса. Предпросмотр показывает карточку в
трёх размерах, полоску в широком и узком окне и страницу целиком.

Главное требование — без лагов: анимации в списке играют только под курсором, остальные карточки — статичные
кадры. Видео в оформлении инстанса в v1 **не** поддерживаем: в списке из десятков карточек это дорого по
декодированию (анимация здесь и так не обязательна; вернёмся к видео, если понадобится). Проверка и декодирование — на стороне Rust (как у иконок), фронт получает уже проверенные
файлы.

### A.4. Где и как показывается

| Место | Что берётся | Анимация |
|---|---|---|
| Список / карточка | `card.image` в покое, `card.hover` при наведении, `accent` | по `card.animate` (по умолчанию при наведении) |
| Хедер инстанса | `header.image` в покое, `header.hover` при наведении | по `header.animate` |
| Страница инстанса | `page.banner`, `page.background`, `logo` | `page.animate`: `always` / `hover` / `never`; пауза при неактивном окне и запущенной игре |
| Звук | `sound.hover` при наведении на хедер, `sound.page` на странице | см. A.6 |

### A.5. Приоритет

`настройки пользователя` → `оформление автора` → `сцена` → `по умолчанию`.

Оформление автора выше сцены: сцена не может его перекрыть. Пользователь одним переключателем
«Оформление от авторов сборок» выбирает: **всё / только статика / выключено**. Отдельно — «Анимации».

### A.6. Звук (версия 2, вместе со сценами)

- Каналы: обои (громкость своя), звук инстанса, общая громкость. Звук инстанса приглушает звук обоев.
- Первая встреча с инстансом, у которого есть звук (импорт или первое открытие): понятное предупреждение —
  «Эта сборка содержит звук. Оставить / Отключить для неё / Никогда не включать звук сборок».
- Наведение: задержка ~400 мс перед стартом и плавное нарастание/затухание; не стрекочет при пролёте мышью.
- Молчит, пока идёт игра и пока окно без фокуса.
- Проверить: разрешает ли WebView2 автовоспроизведение после старта приложения.
- Лицензия на музыку — на авторе. В диалоге экспорта — одна строка-напоминание.

### A.7. Экспорт и импорт

- **Экспорт `.mrpack`:** галочка «Включить оформление ModLEX» (по умолчанию включена) и отдельная
  «Включить звук» (тяжёлый). В экспорт попадает `modlex/` как обычная папка инстанса — экспорт уже
  собирает файлы из папки инстанса по выбранным путям. Итоговый путь в архиве — `overrides/modlex/…`.
- **Отдельная кнопка «Экспортировать кастомизацию»:** пакует только `modlex/` в файл, чтобы переносить
  между своими инстансами или делиться без сборки.
- **Импорт:** `overrides/` распаковывается в папку инстанса, поэтому `modlex/` приезжает сама. Лаунчер
  читает манифест, проверяет, применяет. Чужие лаунчеры видят обычную папку и игнорируют её.
- Манифест из неподдерживаемой версии `schema` — игнорируется целиком без ошибок.

### A.8. Безопасность

- Нет HTML, скриптов, внешних URL и удалённых ресурсов (утечка IP пользователя, подгрузка кода).
- Пути только внутри `modlex/`, проверка на выход за папку (`..`, симлинки).
- Размеры и число файлов проверяются до применения; битый файл не роняет лаунчер.
- Автор может сделать раздражающее оформление — для этого пользовательские переключатели из A.5.

## Часть B. Сцена (ModLEX Scene)

Сцена — набор **независимых частей**. Каждая работает сама, пользователь может собрать фон от одного
автора, раскладку от другого.

### B.1. Слоты

| Слот | Где живёт | Статус |
|---|---|---|
| `background` | под интерфейсом, на всех страницах | есть (HTML-обои) |
| `home` | только страница Home; раскладка, наклоны карточек | частично (наклоны и подсказка раскладки на канале обоев) |
| `card-face` | шаблон лица карточки без скриптов, рисует лаунчер | план |
| `overlay` | поверх контента, `pointer-events: none` | план |

Часть монтируется только там, где слот существует, и полностью размонтируется, когда его нет
(страницы скинов, инстанса, Discover). Одна кнопка отключает сцену целиком.

### B.2. Что лаунчер отдаёт частям (токены и данные)

Есть: `resize`, `theme` (акцент), `state` (пауза: выключена анимация / окно без фокуса / идёт игра),
`pointer`, `cards` (прямоугольники карточек + наведение, по подписке).

План: `pointer.target` (`background` | `ui`) и готовые жесты (drag с дельтой, click, hold, wheel только над
фоном); токены состояния (`instance running`, время игры).

Части не общаются друг с другом напрямую — только через токены лаунчера. Так чужие части не конфликтуют.

### B.3. Что часть может прислать лаунчеру

Есть: `subscribe`, `palette`, `layout`, `card-transforms`, `card-transforms-clear`. Все значения
проверяются и ограничиваются (см. `docs/wallpapers/README.md`).

План:

- **Поза карточки** вместо наклона ±45°: `x, y, z, rx, ry, rz, s, opacity` + перспектива сцены.
  Для 3D-карусели и куба, где грани — карточки инстансов.
- **Режим `stage`** (по желанию сцены, только Home): позиции карточек задаёт сцена, но в границах рамки
  stage; карточки остаются нативными. Без сцены или при нехватке места — обычная раскладка.
- **Сетка главной** данными: колонки/строки/области и варианты по `minWidth`.
- **Шаблон `card-face`**: разметка с плейсхолдерами (`{{name}}`, `{{icon}}`), без скриптов.
  Инстанс с оформлением автора **всегда** рисуется нативно.

### B.4. Манифест сцены

```json
{ "api": 1, "name": "…", "author": "…",
  "parts": { "background": "bg.html", "home": "home.html" },
  "requires": ["cards", "pose"] }
```

`requires` — список возможностей. Лаунчер отвечает, что поддерживает, часть деградирует, если чего-то нет.
Новые возможности сначала выходят как экспериментальные (только в режиме разработчика).

### B.5. Песочница

- Сейчас: `iframe sandbox="allow-scripts"` без `allow-same-origin`. **Сеть песочница сама не режет** —
  это надо закрыть до того, как сцена получит имена инстансов.
- Нужно: отдавать файлы сцены через свой Rust-протокол с заголовком
  `Content-Security-Policy: connect-src 'none'` (и запретом внешних ресурсов). Делается один раз и
  используется всеми частями.

### B.6. Каталог

Отдельный GitHub-репозиторий, не тот же, что у модулей ядра. Формат манифеста и страница модуля
похожи (общий UI-компонент), но у сцен метка доверия другая: «выполняется в песочнице, без доступа к
сети и аккаунтам», а не «не проверено, произвольный код».

## Принятые решения

1. Папка в `.mrpack` — `overrides/modlex/`.
2. Видео в оформлении инстанса в v1 нет; анимация не обязательна, главное — без лагов.
3. Звук инстанса — версия 2, вместе со сценами. **Сейчас** делаем только звук самих обоев (видео и HTML):
   громкость по умолчанию 30 %, ползунок в настройках фона, молчит при запущенной игре и неактивном окне.
   Готово в коде.
4. Лимиты из A.3 приняты, критерий — без лагов.
5. Анимация: по усмотрению автора (`animate`), пользователь может переопределить; по умолчанию — при
   наведении. У хедера и карточки есть картинка «в покое» (`image`) и отдельная при наведении (`hover`).

## Что нужно было решить (архив вопросов)

1. **Путь в `.mrpack`:** `overrides/modlex/` (рекомендую — гарантированно переносится) или отдельная папка
   в корне архива (чище для чужих лаунчеров, но не проверено, что площадки её пропустят).
2. **Видео в оформлении инстанса:** оставить за скобками в v1 (рекомендую) или сразу разрешить.
3. **Звук — в первой версии или второй?** Он тянет за собой предупреждение, микшер и проверку автоплея.
4. **Лимиты из A.3** — подходят ли цифры.
5. **Что показывается в списке** по умолчанию: анимация карточки при наведении (рекомендую) или
   выбор автора без ограничений.

## Статус реализации (2026-09-19)

Готово в коде (дев-сборка, не проверено вживую): Rust — чтение/проверка/запись `modlex/`, импорт/экспорт архивом,
экспорт `.mrpack` с папкой по умолчанию; вкладка «Оформление» в настройках инстанса; показ хедера на главной,
карточки в библиотеке, баннера/фона/логотипа на странице инстанса; настройки «Оформление от авторов сборок» и
«Анимации оформления». Не сделано: звук инстанса (v2), сцены (часть B), точка фокуса в редакторе.

## План работ (предложение)

1. Формат: Rust-часть — чтение/проверка `modlex/modlex.json`, лимиты, безопасные пути, команда «отдать
   проверенный набор».
2. Редактор: вкладки в `icon-editor-modal` (хедер, карточка), запись файлов и манифеста.
3. Показ: хедер и карточка в списке, страница инстанса; переключатели пользователя; анимации с паузой.
4. Экспорт/импорт: галочки, кнопка «Экспортировать кастомизацию».
5. Звук инстанса (v2, вместе со сценой).
6. Сцена: Rust-протокол с CSP → слот `home` → поза карточки и `stage` → `card-face`.
